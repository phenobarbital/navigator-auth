## 1. Motivation & Business Requirements

### Problem Statement

Running the PBAC example (`python examples/policy_server.py`) shows four problems, one functional:

1. **Every URL returns 428** (`{"status":428,"reason":"... No Matching Policies were found, Deny access."}`),
   e.g. `/dashboard/`. `PDP.authorize` asks only the `PolicyEvaluator`, but `PDP.add_policy()` (and the
   `PDP(policies=[...])` constructor argument) only append to `self._policies`, a list the evaluator never
   reads. The example grants `/dashboard/` through `add_policy`, so nothing matches and the deny default
   produces the 428. The gap most likely dates from the April 2026 classic→Rust migration
   (`sdd/specs/migrate-classic-policies-abac-rust.spec.md`), which made `authorize()` evaluator-only while
   promising an unchanged PDP public interface (spec lines 37, 92) and never mentions `add_policy`.
2. **Log noise** — `Access to /favicon.ico is not Authenticated.` (and `/.well-known/...`,
   `/client-config`) at WARNING on the root logger. Research found the cause is a bug, not missing
   exclusions: `abac_middleware`'s 404 skip wraps `await handler(request)` in `try/except Exception: pass`,
   so the `HTTPNotFound` raised by the 404 handler is swallowed, the request falls through to the WARNING,
   and the 404 handler runs a second time (reproduced with aiohttp 3.14.3).
3. **`InsecureKeyLengthWarning: The HMAC key is 6 bytes long`** — `AUTH_SECRET_KEY` is 6 characters in
   `env/.env` (same length in `env/prod/.env`; both untracked by git), `PARTNER_KEY` (fallback for
   `AUTH_TOKEN_SECRET`) is 16 bytes, and nothing checks key length at startup.
4. **`Vault secret failed integrity check: user=35 key=account error=UnsupportedFormatError`** — a
   pre-FEAT-099 (v1) vault blob that was never migrated to the v2 envelope. Skipping it is the designed
   fail-closed behaviour of `navigator-session`; the remedy is the `navigator-vault migrate` runbook.

### Goals

- **G1** — A policy registered with `PDP.add_policy()` or `PDP(policies=[...])` is enforced by
  `PDP.authorize` (classic `Policy`, `ObjectPolicy`, `FilePolicy` and `ResourcePolicy` alike), survives
  `reload_policies()`, and reaches per-tenant evaluators.
- **G2** — The startup "skip storage load when the evaluator is pre-populated" guard keeps working for
  externally pre-loaded evaluators and is not tripped by policies registered through `add_policy`.
- **G3** — `abac_middleware` skips unrouted (404) requests correctly: no log line, handler called once.
  The unauthenticated pass-through message is logged at DEBUG.
- **G4** — `AuthHandler.setup` logs one security WARNING per configured HMAC key shorter than 32 bytes,
  naming the setting and its byte length (never the value).
- **G5** — `examples/policy_server.py` uses the documented registration path only, and
  `examples/README.md` documents running it plus troubleshooting (428, short keys, v1 vault secrets).

### Non-Goals (explicitly out of scope)

- No new default auth exclusions. `/favicon.ico` and `/.well-known/*` are **not** added to
  `EXCLUDE_DEFAULTS`: the exclude list also bypasses authentication (`auth.py:958`), and the 404 fix
  already removes the noise (decided 2026-11-11, see §8).
- No change to the `_load_policies` pre-load guard semantics for externally loaded evaluators, and no
  change to the fact that `reload_policies()` rebuilds only from storage plus registered policies
  (policies pushed straight into the evaluator by hand are still dropped on reload — existing behaviour).
- No change to the deny default, the Rust engine, or `SubjectSpec.matches_user` (Python) semantics.
- No vault code change: `SessionVault` and the v2 envelope live in `navigator-session`; migrating user
  35's secret is an operator step (`navigator-vault migrate`).
- No rotation of real secrets by a task: `env/` is git-ignored (`.gitignore:113`); rotating
  `AUTH_SECRET_KEY` / `PARTNER_KEY` / `AUTH_TOKEN_SECRET` is an operator step.
- Not fixing the pre-existing name/status mismatch of `PreconditionFailed` (428 vs 412).

## 2. Architectural Design

### Overview

**428 fix (library).** `PDP` gains a registry of programmatic policies, `self._registered:
list[ResourcePolicy]`. `PDP.add_policy(policy)` converts the policy with a new
`PolicyAdapter.from_policy()` (pass-through for `ResourcePolicy`; classic objects are turned into the
classic dict shape that `PolicyAdapter.adapt()` already understands), records the result in
`_registered` and `_policies`, loads it into the shared evaluator, clears the evaluator's decision cache
and drops cached per-tenant evaluators. The constructor's `policies=` argument goes through the same
path. Conversion needs the original resource strings — `Resource` objects lose them for non-URI URNs —
so `AbstractPolicy.__init__` also records `raw_resources: list[str]` and fixes string-resource
construction to use `[Resource(resource)]` instead of `list(Resource(resource))`.

`add_policy` fails loudly: a policy the adapter skips (e.g. an invalid regex) or a name already
registered raises `ValueError`. A silently ignored policy is the failure mode this feature removes.
Before calling the legacy dict adapter, `from_policy` rejects classic policies with non-empty
`context`, `conditions`, or `scopes`: the existing conversion/evaluator does not preserve those
restrictions. It validates every resource, including negated patterns, and rejects the whole policy
if any pattern is invalid. A warning alone is not successful adaptation. These stricter checks apply
to the new programmatic conversion path; the existing storage dict adapter remains unchanged.

Classic environment conditions normalize `day_of_week` to the engine's `dow` key before adaptation.
Conflicting alias values or unsupported environment keys/shapes cause rejection, never silent removal.
The example's `prod_config_manager` uses `subject=["platform-lead@acme.com"]` instead of its unsupported
username context restriction, preserving the intended user-specific grant.

The startup guard in `_load_policies` changes from "skip when the evaluator index is non-empty" to "skip
when the evaluator holds policies that were **not** registered through `add_policy`" (identity check
against `_registered`). An externally pre-loaded evaluator still skips storage (pinned by
`TestPDPDoubleLoadPrevention`); a PDP whose evaluator holds only registered policies — e.g.
`examples/test_abac.py`: `PDP(storage)` plus nine `add_policy` calls — still loads DB and YAML.

`reload_policies()` appends `_registered` to the storage policies before building the new index, and
`_build_tenant_evaluator()` appends them before `ev.load_policies(...)`. Tenant scoping stays with the
engine (`org_id`/`client_id` on each `ResourcePolicy`, default `(1, 1)` = global).

An adapted classic policy with no groups/users/roles matches every subject in the Rust engine
(`navigator_auth/rs_pep/src/lib.rs:222-225`), so `public_dashboard` grants `/dashboard/` once registered.

**Log noise.** `abac_middleware` computes "is this a system route?" inside a guarded helper and calls
the handler outside any `try`. The unauthenticated pass-through logs at DEBUG. The duplicated, unreachable
`except (TypeError, KeyError)` clause is removed. `EXCLUDE_DEFAULTS` is unchanged.

**Short keys.** New module `navigator_auth/libs/hmac_keys.py` measures the configured HMAC keys
(`SECRET_KEY` ← `AUTH_SECRET_KEY`, `AUTH_TOKEN_SECRET` ← `PARTNER_KEY` fallback, `AUTH_RECOVERY_SECRET`
when set explicitly) and logs one WARNING per key under 32 bytes on the `navigator_auth.security` logger.
`AuthHandler.setup` calls it once. It logs; it never raises and never uses `warnings.warn` (pytest runs
with `filterwarnings = ["error"]`).

**Example.** `examples/policy_server.py` stops pre-loading the evaluator by hand: the five
`ResourcePolicy` objects and the five classic policies are all registered with `pdp.add_policy`, and the
default packs load from `yaml_storage` at startup. `examples/README.md` gains a `policy_server.py`
section with troubleshooting for the 428, short keys and v1 vault secrets.

### Data Models

No new Pydantic models. `PolicyAdapter.from_policy` emits the existing classic policy dict shape:

```python
{
    "policy_type": "policy" | "object" | "file",
    "name": str, "description": str | None,
    "effect": "ALLOW" | "DENY",
    "resource": list[str],          # AbstractPolicy.raw_resources, verbatim
    "actions": list[str],           # "object:action" from ActionKey
    "subject": list[str],           # [] when None
    "groups": list[str],            # [] when None
    "context": {},                  # non-empty classic context is rejected before conversion
    "environment": dict | None,     # validated; day_of_week normalized to dow
    "priority": int, "enforcing": bool,
    "objects": dict | None,
    "org_id": int, "client_id": int,  # from policy.attributes, default 1
}
```

Non-empty classic `conditions` and `scopes` are also rejected before this dict is emitted; their
omission must never silently weaken a policy. Rejection returns `AdapterResult(skipped=True,
reason=...)` with no policy or additional policies. `PDP.add_policy` turns that result into
`ValueError` before changing any registry, evaluator, or cache.

### Module 1: Policy-object adapter

- **Path**: `navigator_auth/abac/policies/adapter.py`, `navigator_auth/abac/policies/abstract.py`
- **Responsibility**: Convert a programmatic policy object (`Policy`, `ObjectPolicy`, `FilePolicy`, or
  `ResourcePolicy`) into evaluator-ready `ResourcePolicy` objects without losing resource strings.
- **Depends on**: existing `PolicyAdapter.adapt` (adapter.py:89)
- **Interface Skeleton**:
  ```python
  # navigator_auth/abac/policies/abstract.py  (modifies AbstractPolicy.__init__, abstract.py:67-124)
  class AbstractPolicy(ABC):
      def __init__(self, name: str = None, ..., resource: Union[list, str] = None, ...):  # verified: abstract.py:67
          ...
          # NEW, next to the resource handling at abstract.py:94:
          self.raw_resources: list[str]
          """Resource strings exactly as passed: a str becomes [str], a list is copied
          (items str()-ed), None becomes []. Used by PolicyAdapter.from_policy.
          FIX: the str branch sets self.resources = [Resource(resource)], so construction
          succeeds and retains the same Resource semantics as a one-item list."""

  # navigator_auth/abac/policies/adapter.py  (modifies; new method before adapt_batch, adapter.py:276)
  class PolicyAdapter:
      @staticmethod
      def from_policy(policy: AbstractPolicy) -> AdapterResult:
          """Adapt a policy object for the PolicyEvaluator.

          ResourcePolicy -> AdapterResult(policy=policy), unchanged.
          FilePolicy -> policy_type "file"; ObjectPolicy -> "object"; any other
          AbstractPolicy -> "policy". Classic objects are converted to the classic
          dict shape (spec §2 Data Models; resource = policy.raw_resources) only after
          the validation contract below succeeds, then passed to PolicyAdapter.adapt().
          Never raises: failures come back as
          AdapterResult(skipped=True, reason=...).
          """
  ```
  Check order: `ResourcePolicy` first (it subclasses `AbstractPolicy`, resource_policy.py:7), then
  `FilePolicy` before `ObjectPolicy` (file.py:8 subclasses obj.py:8). New imports in adapter.py must be
  absolute (`from navigator_auth.abac.policies.<mod> import ...`), matching adapter.py:5-7; no cycle
  (policy/obj/file modules do not import the adapter).

  **Classic conversion validation contract (before calling `adapt`):**
  - Reject non-empty `context`, `conditions`, or `scopes` with a reason naming the unsupported
    restriction. Do not drop them, merely warn, or rely on `python_conditions` (the evaluator does
    not enforce that attribute). This applies to ALLOW and DENY policies alike.
  - Convert and validate every supplied resource, including `!`-prefixed resources, using the
    existing URN conversion and pattern validation helpers. Any invalid pattern rejects the entire
    input, including mixed valid/invalid lists; no partial allow or generated deny may escape.
    An explicitly empty resource list retains the existing unrestricted semantics, but filtering
    invalid input down to an empty list is forbidden. Adapter warnings about lost resources must
    likewise be treated as failure, not successful registration.
  - Copy the environment mapping; normalize `day_of_week` to `dow`. If both keys occur, accept
    equal values and reject conflicting values. Accepted engine keys are `hour`, `dow`,
    `is_business_hours`, `is_weekend`, and `day_segment`. Accept scalar equality, lists of scalar
    values, and numeric range dictionaries with only `min`/`max` and at least one bound; reject
    unsupported keys, shapes, and incompatible value types. Do not mutate the source policy.
  - Keep valid `ResourcePolicy` objects as pass-through; do not reinterpret their native conditions
    through the classic conversion path.

## 7. Implementation Notes & Constraints

### Patterns to Follow

- Adapter methods are `@staticmethod`s returning `AdapterResult`; failures are reported, not raised
  (`adapter.py:101-102`). `PDP.add_policy` is the place that turns a skip into `ValueError`.
- Per-tenant evaluators are rebuilt lazily; invalidate with `_invalidate_tenant_evaluators()`
  (`pdp.py:233`), as `reload_policies` does (`pdp.py:310-314`).
- Security-relevant log lines go to the `navigator_auth.security` logger (`middlewares/probes.py:31`).
- Guard tests use `_make_fake_evaluator` (`tests/test_yaml_storage_double_load.py:206`): a `MagicMock`
  with a `_FakeIndex`. `_has_external_policies` must only use `self._evaluator._index.all()` so these
  fakes keep working.
- Google-style docstrings and type hints on every new function (project rule).

### Known Risks / Gotchas

- **pytest turns warnings into errors** (`pyproject.toml:109-125`, `filterwarnings = ["error", ...]`).
  The key check must log, not `warnings.warn`. Tests that build an app with a short test key must not
  trip PyJWT's own `InsecureKeyLengthWarning` either — use ≥ 32-byte keys in new fixtures.
- **Identity, not equality**, for the guard: compare with `id()` against `_registered`; `ResourcePolicy`
  equality semantics are not relied on.
- **`PolicyIndex.add` does not de-duplicate** (`evaluator.py:97-108`). `add_policy` refuses duplicate
  registered names; a registered name that collides with a storage/YAML policy loaded later is not
  detected (existing behaviour for storage duplicates). Example names are disjoint from the default
  packs today (checked 2026-11-11).
- **`load_policies` does not clear the decision cache** (`evaluator.py:240-246`); `add_policy` must call
  `invalidate_cache()` or an earlier cached deny can persist for up to `cache_ttl_seconds` (300 s).
- **Python vs Rust subject semantics differ**: `SubjectSpec.matches_user` returns False for empty
  subjects (`resources.py:147-169`) while the Rust engine matches everyone (`lib.rs:222-225`). Only the
  engine decides `authorize`; do not "fix" either side here.
- **`raw_resources` for a str `resource`**: `AbstractPolicy.__init__` does `list(Resource(resource))`
  for a str (`abstract.py:94-95`), which raises `TypeError` because Resource is not iterable.
  M1 must capture `raw_resources` and replace that expression with `[Resource(resource)]`.
  Test real construction; assigning `raw_resources` on a mock does not cover this regression.
- **`self._policies` aliasing**: today `PDP(policies=lst)` stores the caller's list object
  (`pdp.py:80-81`). After M2 the PDP keeps its own list; callers that mutated `lst` afterwards were
  never enforced anyway.
- **Compiled engine**: tests need the `rs_pep` extension (`evaluator.py:223-227`). Worktrees receive it
  through the native-artifact sync; never run `maturin develop` inside a worktree.
- **Example still needs Postgres/Redis to run**; automated example tests import its policy objects
  and exercise the real evaluator with mocked storage for registration, reload, and tenant builds.
  They require no live DB/Redis; the running app remains an operator check (§5).

### Design Decisions

> Recorded as prose: decision audit is not configured in this repository, so a `## Decisions` YAML
> block is rejected by `parrot sdd spec consequences` (`AUDIT_NOT_CONFIGURED`).

- **`add_policy` is enforced and fails loudly.** Policies registered through `PDP.add_policy` or
  `PDP(policies=...)` are adapted and loaded into the `PolicyEvaluator`, kept across `reload_policies`
  and per-tenant evaluators; an unadaptable policy or a repeated registered name raises `ValueError`.
  *Rationale*: `authorize()` has been evaluator-only since the classic→Rust migration, which promised an
  unchanged PDP public interface. *Rejected*: example-only fix (leaves every `add_policy` caller
  broken); log-and-skip on adapter failure (reproduces the silent no-match).
- **No probe-path exclusions.** `/favicon.ico` and `/.well-known/*` are not added to the default auth
  exclude list; unrouted requests are skipped by the ABAC middleware's system-route check.
  *Rationale*: the exclude list also bypasses authentication (`auth.py:958`), so a `/.well-known/*`
  default would make routed well-known endpoints public. *Rejected*: default exclusions for both paths.
- **Reject unsupported classic restrictions rather than weakening authorization.** The new
  `from_policy` path rejects non-empty `context`, `conditions`, and `scopes`, validates resources
  atomically, and normalizes supported environment conditions. No Rust engine change or broad
  storage-adapter migration is required. The example expresses its username restriction using
  `subject`. *Rejected*: warning-and-continue conversion, which reproduced an unrelated user's
  access to production config and an invalid regex becoming an unrestricted grant.
